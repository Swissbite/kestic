Kestic 0.5.0 backs up to more places. Besides a local folder and a REST server, a destination can now be an SSH server (SFTP), S3-compatible storage, Backblaze B2, Azure, Google Cloud, Swift, or any rclone remote. An SSH server is reached with your SSH key or ssh-agent; Kestic shows the fingerprint of a server it does not know and remembers its key only after you trust it. S3 keys and secret variables stay in the password store. External drives are listed when they are plugged in, and a destination type that needs a program you have not installed names the package.

You can edit a destination's connection: move it to another address or path, or change its credentials. Before it saves, Kestic checks that the new connection reaches the same repository; a different repository can be added as a new destination instead.

Kestic no longer depends on the restic of your system. With the restic source «Automatic» it uses the system restic if it is 0.18.0 or newer, otherwise one managed by Kestic. Kestic downloads the official restic release only when you ask, checks its signature and checksums, and never replaces it while a backup or restore uses it.
