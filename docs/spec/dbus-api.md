# D-Bus-API Daemon ↔ GUI

Verbindliche Spezifikation für v1 (F14, U17, U18, M1-S09, AC-M1-09-5). Jede Erweiterung in späteren Meilensteinen wird hier nachgeführt.

## Grundsätze

- **Bus-Name (Single-Instance-Lock):** `net.daester.Kestic` (Session-Bus, `DO_NOT_QUEUE`). Ein zweiter Daemon erkennt `AlreadyRunning` und beendet sich sofort mit Exit 0 (F14, AC-M1-09-1).
- **Objektpfad:** `/net/daester/Kestic`
- **Interface (versioniert):** `net.daester.Kestic1` — inkompatible Änderungen nur über ein neues Interface (`net.daester.Kestic2`).
- **Alleiniger Schreiber:** Nur der Daemon schreibt `config.toml`, `history.db`, Excludes und Logs (F14, AC-M1-09-3). Die GUI liest Zustand über `GetState` / Signale und schreibt ausschliesslich über die D-Bus-Methoden. `core` validiert jede Änderung serverseitig; ungültige Eingaben liefern einen D-Bus-Fehler, ohne `config.toml` zu verändern (AC-M1-09-2).
- **Secrets:** Passwörter werden nur für den Moment der Einrichtung/Prüfung/Änderung über den Session-Bus entgegengenommen, sofort über `SecretStore` (KWallet / Secret Service) abgelegt bzw. gelöscht und **nie** in `config.toml`, `GetState` oder Signalen zurückgegeben (NFR-02).
- **Daemon-Start:** Die GUI startet bei Bedarf `kestic daemon` ohne `--autostart` (M1-S21). Autostart nutzt `kestic daemon --autostart` und beendet sich ohne `config.toml` sofort mit Exit 0 (M1-S12).

## Fehler-Namen (`net.daester.Kestic.Error.*`)

Der Fehler-Name ist der Code: `KesticDbusError` (`kestic_daemon::dbus_api`, von Daemon und GUI gemeinsam genutzt) liefert ihn als `kestic_i18n::codes::ServiceErrorCode`, und `kestic_i18n::messages` bildet ihn auf die msgid ab, wie bei den DTO-Codes. Die GUI unterscheidet Varianten, nie Namens-Strings, und zeigt den Text des Codes in ihrer Sprache.

- **Die Meldung ist Rohdetail.** Sie dient Log und Details-Ansicht und ist nie der Haupttext in der UI. Der Daemon übersetzt sie nicht; unerwartete Fehler (`InvalidInput`, `Internal`) schreibt er ins Session-Journal. Bei `ManualRunBlocked` ist die Meldung der Code aus `BlockedReason`.
- **Eigener Text braucht eigenen Fehler-Namen** (z. B. `LockInUse`), nie eine Kennung in der Meldung.
- **Ergebnisse mit Parametern sind keine Fehler.** Was die GUI mit Parametern anzeigen muss (z. B. «Ziel /x existiert bereits», ab M4 Restore), kommt als Status-DTO mit Code und typisierten Feldern zurück, wie `ConnectionTestResultDto` oder `BackupDryRunStatusDto`.
- Ohne Fehler-Namen (Transportfehler, Daemon nicht erreichbar) gilt der Code `DaemonUnreachable`.

| Fehler-Name | Bedeutung |
| --- | --- |
| `net.daester.Kestic.Error.InvalidInput` | Validierung in `core` oder D-Bus-Argument fehlgeschlagen (AC-M1-09-2) |
| `net.daester.Kestic.Error.NotFound` | Ziel-, Backup- oder Lauf-ID unbekannt |
| `net.daester.Kestic.Error.InUse` | Ziel wird noch von Backups referenziert und kann nicht entfernt werden (AC-M1-19-4), oder ein Restore von diesem Ziel startet, wartet oder läuft (`RemoveDestination`, `UpdateDestination`) |
| `net.daester.Kestic.Error.ManualRunBlocked` | Quelle nicht verfügbar (`source_unavailable`) oder Ziel nicht erreichbar (`destination_unreachable`) vor manuellem Start (FR-30, AC-M1-09-6) |
| `net.daester.Kestic.Error.DestinationUnreachable` | Vorab-Check (`P32`) fehlgeschlagen (Timeout 10 s / ≤ 15 s) |
| `net.daester.Kestic.Error.WrongPassword` | Repository-Passwort abgelehnt (Exit 12, AC-M1-06-3, AC-M1-20-2) |
| `net.daester.Kestic.Error.AuthFailed` | Backend-Anmeldung (z. B. REST 401/403) fehlgeschlagen (AC-M1-06-6) |
| `net.daester.Kestic.Error.SecretStoreLocked` | Passwortspeicher gesperrt oder nicht erreichbar |
| `net.daester.Kestic.Error.ResticUnavailable` | `restic` fehlt, ist `< 0.18.0` oder nicht ausführbar |
| `net.daester.Kestic.Error.AlreadyRunning` | Auf dem betroffenen Ziel bzw. Backup läuft bereits ein Lauf; bei `StartRestore`: ein Restore in denselben (aufgelösten) Zielordner startet, wartet oder läuft |
| `net.daester.Kestic.Error.LockInUse` | Entsperren abgelehnt: Die Repository-Sperre gehört zu einem aktiven oder entfernten Prozess (P16) |
| `net.daester.Kestic.Error.DuplicateLocation` | Der Speicherort wird bereits von einem anderen Ziel verwendet; Meldung = Name dieses Ziels (Rohdetail) |
| `net.daester.Kestic.Error.PreviewRequired` | `StartRestore` ohne passende, frische Vorschau: Ziel ist der Originalort oder ein nicht leerer Ordner, und `preview_id` fehlt, gehört zu anderen Parametern, ist nicht `done` oder älter als 10 Minuten (F5, NFR-08, M4-S05) |
| `net.daester.Kestic.Error.Internal` | Unerwarteter I/O-, SQLite- oder Prozessfehler |

Ergänzte DTO-Felder ab M2/M3: `BackupSummaryDto` trägt zusätzlich `pending_forget` (M2-S07), `nested_warnings` (M2-S10), `exclude_lint_warnings` (M2-S03) sowie `is_paused`, `paused_since_unix`, `paused_until_unix`, `next_scheduled_at_unix`, `pending_primary_code`, `pending_reason_codes`, `pending_retry_at_unix`, `missed_slots_count`, `has_unmet_run_condition`, `unmet_run_conditions` und `battery_percent` (M3); `BackupAvailabilityDto.source_status` nennt den Laufwerks- oder Quellenfehler als Code (`M2-S09`); `DestinationSummaryDto` trägt Wartungszeitpunkte (`next_prune_at_unix`, `next_check_at_unix`, `last_prune_at_unix`, `last_check_at_unix`, `last_maintenance_run`, `maintenance_running`, `pending_forget_count`, `stale_lock_count`, `maintenance_pending_reason`, `maintenance_retry_at_unix`); `OverallStatusDto` trägt Pause-Metadaten (`paused_since_unix`, `paused_until_unix`, `next_scheduled_backup_name`, `next_scheduled_at_unix`).

**Snapshot-Abfragen und Restore (ab M4):** Ein gemeinsames Trio `StartSnapshotQuery` / `GetSnapshotQueryStatus` / `CancelSnapshotQuery` trägt alle lang laufenden Abfragen (`ls`, `find`, `diff`, Restore-Vorschau); der Zielvorschlag für den Restore kommt im Ergebnis der Vorschau mit. Restore selbst ist ein Lauf der Art `Restore`.

- `SnapshotSummaryDto` (erweitert): `id`, `short_id`, `time`, `hostname`, `paths`, `tags`, `total_bytes_processed`, `total_files_processed`, neu `data_added` (`Option<u64>`), `username` (`Option<String>`), `uid` (`Option<u32>`). Fehlen die Zahlen (Snapshot ohne Zusammenfassung), sind sie `null` (AC-M4-01-5).
- `DestinationSnapshotsDto`: `destination_id`, `error_kind`, `error_detail`, `backups` (`BackupSnapshotCountDto`: `backup_id`, `backup_name`, `count`, `latest_time`), `unassigned` (Snapshots), `orphaned` (`OrphanedBackupDto`: `backup_id`, `count`, `latest_time`, `latest_hostname`, `snapshots`).
- `SnapshotQueryRequest`: `kind` (`SnapshotQueryKind`) und `destination_id`, dazu je Art:
  - `ls`: `snapshot_id`, `dir` (absolut; immer genau ein Ordner, nie rekursiv).
  - `find`: `pattern`, `scope` (`backup` mit `backup_id` \| `unassigned` \| `orphaned` mit `backup_id`).
    - `pattern` ist der Suchtext des Benutzers, kein restic-Muster: Er trifft jeden Pfad, der ihn wörtlich enthält, ohne Rücksicht auf Gross-/Kleinschreibung. Der Daemon baut daraus `*<text>*` und ruft `restic find --ignore-case … -- <muster>` nur über die Snapshot-IDs des `scope` auf (höchstens 1000 je Aufruf). `*`, `?`, `[`, `\` und `!` maskiert er mit `\`, `--` steht vor dem Muster (ein Text mit führendem `-` ist kein Flag).
    - Ein führendes `/` beginnt ein Pfadsegment: `/home/u/Dokumente` wird zu `home/u/Dokumente*` und findet so auch einen eingefügten absoluten Pfad. Ein Text mit einem leeren, `.`- oder `..`-Segment zwischen zwei `/` kommt in keinem Snapshot-Pfad vor und liefert ohne restic-Aufruf keine Treffer (restic würde das Muster sonst wie einen Pfad bereinigen).
    - restic vergleicht jede Folge von Pfadsegmenten; ein Ordner-Treffer bringt deshalb auch alle Einträge darunter mit (seitenweise, an der Speichergrenze «Zu viele Einträge für die Anzeige»).
    - Bekannte Grenze: keine Unicode-Normalisierung; ein in NFC getippter Text findet keinen Namen in NFD (z. B. von macOS oder SMB).
  - `diff`: `from_snapshot_id`, `to_snapshot_id`.
  - `restore_preview`: `snapshot_id`, `selection` (absolute Snapshot-Pfade, leer = alles), `target` (optional, `{"kind": "new_folder" | "original", "dir": …}`: `new_folder` mit dem vorgeschlagenen oder gewählten Ordner \| `original` mit dem abgebildeten `dir`; bei `StartRestore` Pflicht), `overwrite` (`RestoreOverwrite`, Standard `never`). Ohne `target` nimmt der Daemon den vorgeschlagenen neuen Ordner.
- `SnapshotQueryStatusDto`: `state`, `error_kind`, `error_detail` und `result`, getaggt nach `kind`: `LsResultDto`, `FindResultDto`, `DiffResultDto` oder `RestorePreviewResultDto`. `result` gibt es erst bei `done`.
- **Grosse Listen seitenweise, nie gekappt:** Der Daemon hält die vollständige Liste jeder Abfrage (Ordnerinhalt, Suchtreffer, Änderungen, Einträge der Vorschau) und gibt sie seitenweise heraus. Die GUI lädt beim Scrollen nach (`QAbstractListModel` mit `canFetchMore`/`fetchMore`).
  - `SnapshotQueryPage` (`page_json`): `offset` (`u64`, Standard 0), `limit` (`u32`, 1–1000, Standard 200), `filter`: `text` (Teilstring im Pfad, Gross-/Kleinschreibung egal; bei `ls` im Namen des Eintrags, weil die Liste nur einen Ordner zeigt) und `kinds` (Liste von Codes: `SnapshotChange` bei `diff`, `RestoreOutcome` bei `restore_preview`; leer = alle). Gefiltert wird im Daemon.
  - Jede Liste kommt als `ListPageDto`: `items` (die Seite), `offset`, `total` (alle Einträge der Abfrage), `matched` (Einträge, die zum Filter passen; ohne Filter = `total`) und `too_large`. Die Zähler eines Ergebnisses (z. B. `added_files`, `new_files`) zählen immer die ganze Abfrage, unabhängig vom Filter.
  - Reihenfolge fest je Abfrage: Pfad aufsteigend, bei `find` zuerst Snapshot-Zeit absteigend; gleiche Seite, gleiche Einträge.
  - **Speichergrenze:** Die Listen aller gehaltenen Abfragen zusammen belegen höchstens 512 MiB, eine einzelne höchstens 256 MiB, gerechnet als Pfadlänge in Bytes plus 64 Bytes je Eintrag. 256 MiB reichen für rund eine Million Pfade mittlerer Länge, auch die eines ganzen Heimordners in einer Vorschau. Ein Desktop-Daemon soll trotzdem nicht unbegrenzt wachsen. Überschreitet eine Liste ihre Grenze, verwirft der Daemon nur die Liste: Zähler und `total` bleiben genau, `too_large` ist `true`, `items` leer, und die GUI sagt das, statt still zu kürzen. Braucht eine neue Abfrage Platz über der Gesamtgrenze, gibt der Daemon zuerst die am längsten nicht abgerufenen fertigen Abfragen frei.
- `LsResultDto`: `dir`, `dir_exists`, `entries` (`ListPageDto` von `name`, `path`, `entry_type`, `size`, `mtime`, `uid`, `hard_links`). `dir_exists` stammt aus dem ersten Knoten; restic liefert für einen fehlenden Ordner nur eine leere Ausgabe.
- `FindResultDto`: `hits` (`ListPageDto` von `snapshot_id`, `snapshot_time`, `path`, `entry_type`, `size`, `backup_id`), `snapshots_matched`; `total` 0 heisst «keine Treffer».
- `DiffResultDto`: `changes` (`ListPageDto` von `path`, `change`), `added_files`, `removed_files`, `changed_files`, `bytes_added`, `bytes_removed`, `identical` (für «keine Unterschiede»).
- `RestoreRequest` (für `StartRestore`): `destination_id`, `snapshot_id`, `selection`, `target` (Pflicht), `overwrite` wie bei `restore_preview`, dazu `preview_id` (`Option<String>`: `query_id` einer fertigen `restore_preview`). Eine Vorschau ohne `target` zählt für das Ziel, das ihr Ergebnis unter `target` nennt.
- **Lebensdauer von Abfragen:** Fertige Ergebnisse (`done`, `cancelled`, `error`) bleiben 10 Minuten nach dem letzten Abruf abrufbar (über `Clock`) oder bis die Speichergrenze sie verdrängt; danach liefert `GetSnapshotQueryStatus` `NotFound`, und die GUI startet die Abfrage neu. Für `StartRestore` zählt davon unabhängig, dass die Vorschau höchstens 10 Minuten seit ihrem Ende alt ist.
- `RestorePreviewResultDto`:
  - `suggestion`: `new_folder` (Pfad) und `original` (`original_dir`, `mapped_dir`, `mapping` alt → neu, `needs_user_choice`).
  - `target`: das verwendete Ziel mit `check` (`RestoreTargetCode` und `detail`), vom Daemon geprüft.
  - Zähler `new_files`, `overwritten_files`, `kept_files`, `identical_files` und `bytes_to_write`; für die Trennung von «nicht überschrieben» und «unverändert» fährt der Daemon bei Modus ≠ `always` einen zweiten Probelauf (`restore --dry-run`) mit `--overwrite always`.
  - `entries` (`ListPageDto` von `path`, `outcome`, `size`); `notes` (`RestoreNoteCode`).
  - Beim Standardziel (neuer, leerer Ordner) fährt die Vorschau keinen Probelauf: Sie liefert nur `suggestion` und `target`, die Zähler und `entries` bleiben leer, weil dort ohnehin alles neu ist.
- **Ablauf im Dialog:** Beim Öffnen startet die GUI eine `restore_preview` ohne `target` und erhält Vorschlag und Prüfung. Wählt der Benutzer den Originalort oder einen anderen Ordner, läuft eine neue Vorschau mit diesem Ziel; ihre `query_id` geht als `preview_id` an `StartRestore`.
- **Erweitert:** `RunDetailDto` trägt `restore` (`RestoreStats`: `files_new`, `files_overwritten`, `files_kept`, `bytes_restored`, `target_dir`, `overwrite`, `selection_count`; gespeichert in `runs.stats_json`, wie `MaintenanceStats`). `ActiveRunProgressDto` und das Signal `RunProgress` tragen zusätzlich `kind` (`RunKindCode`: `backup`, `maintenance`, `restore`, `meta`); `RestoreStats` liegt wie `MaintenanceStats` im `Run` (`Run.restore`); `backup_id` und `backup_name` sind optional, weil Restores ohne Backup-Bezug (fremde Snapshots) keinen haben. `CancelRun` und die Signale bleiben unverändert.

**Sprachunabhängige Codes (Variante A+, Entscheid 2026-11-20):** Die API ist privat (Daemon und GUI im selben `.deb`, keine anderen Aufrufer), Rückwärtskompatibilität ist deshalb kein Ziel. Vertrag sind Codes, nicht Texte:

- **Keine Texte in Daemon-Sprache in DTOs.** Die DTOs tragen Codes, Zahlen und Rohdaten. Texte entstehen erst dort, wo sie angezeigt werden: die GUI übersetzt in ihrer Sprache (KI18n), der Daemon für Tray, Benachrichtigungen und Lauf-Historie in seiner (`daemon/src/i18n.rs`). Beide lesen `po/de/kestic.po`. Die GUI kennt keinen Rückfall auf Daemon-Texte.
- **Typisierte Codes.** Jeder Code ist ein Rust-Enum in `kestic_i18n::codes` (ausser `TrayStatus` im Daemon) und wird als `snake_case`-String serialisiert; `kestic-core` wandelt seine Fach-Typen in diese Codes um. Unbekannte Codes sind ein Deserialisierungsfehler; ein unbekannter Grund im Signal `ManualRunBlocked` wird ignoriert, nie geraten.
- **Genau eine Abbildung Code → msgid.** `kestic_i18n::messages` liefert pro Code die englische msgid samt Parametern (`Message`); Rohdaten, die unverändert angezeigt werden, kommen als `UiText::Raw`. Die msgids sind mit `i18n_noop("…")` markiert und werden mit `xgettext --keyword=i18n_noop:1` extrahiert. Daemon und GUI haben keine eigenen `match`-Tabellen über Codes.
- **Rohdaten bleiben Daten.** `error_detail` (auch in `SkippedBackupDto`, `BackupDryRunStatusDto`, `RetentionPreviewStatusDto`), `error_raw_detail`, `ResticStatusDto.detail`, `SecretStoreStatusDto.detail`, `ConnectionTestResultDto.detail`, `DestinationAvailabilityDto.detail`, `BackupSnapshotsDto.current_error` und `config_load_error` enthalten den unübersetzten, englischen Text von restic, System oder `core` (Fehlertexte in `core` sind englisch) und dienen als Detail bzw. Parameter. Angezeigt wird ein Rohtext nur dort, wo der Code keinen eigenen Text hat (`unknown`, bei `ConnectionTestResultDto` die Codes `invalid_input`, `internal`, `command_failed`, `daemon_unreachable`).
- **Fehler.** D-Bus-Fehler folgen derselben Regel; siehe §Fehler-Namen.

## Texte und Übersetzungen

Jeder Text hat genau einen Ort:

- **Gemeinsame Texte** (Daemon **und** GUI brauchen sie): im Crate `kestic-i18n` (`i18n/src/`). Das sind die Texte der Codes, Status-Texte wie «Schedules paused» oder «Paused since %1» und Labels, die Tray und Fenster zeigen (`messages::Label`, in QML über das Singleton `Texts`). Markiert mit `i18n_noop("…")`.
- **Nur GUI, an einer Stelle:** als `i18n("…")` in der einen Datei unter `gui/src` bzw. QML, die ihn zeigt (Labels, Hilfetexte, Formular-Prüfungen, GUI-eigene Status-Zeilen).
- **Nur GUI, an mehreren Stellen:** einmal im Register `gui/src/ui_texts.rs` (`GuiText`, markiert mit `i18n_noop("…")`). Rust nutzt die Variante (`GuiText::Close.text()`), QML den Code (`Texts.label("close")`, mit Parametern `Texts.labelArgs("two_parts", [a, b])`). Gleiche Formularteile (z. B. das Ziel-Formular der beiden Assistenten und der Bearbeitungsseite) sind eine gemeinsame QML-Komponente statt kopierter Texte.
- **Nur Daemon:** als `i18n("…")` in `daemon/src` (Tray-Menü, Benachrichtigungen, Lauf-Historie).
- `kestic-i18n` übersetzt nie; Daemon und GUI übersetzen mit ihrer eigenen i18n aus `po/de/kestic.po`.
- Kein Text doppelt, auch keine reinen UI-Labels: Jede `msgid` steht als Literal (`i18n`, `i18nc`, `i18np`, `ki18n`, `i18n_noop`) in genau einer Produktionsdatei unter `daemon/src`, `gui/src` (Rust und QML) und `i18n/src`; Tests und Smoke-Harness zählen nicht. Kein Literal wiederholt einen Text aus `kestic-i18n`, und kein Literal steht in Daemon und GUI zugleich. Gleicher Sinn heisst gleicher Wortlaut. Der Test `i18n/tests/text_ownership.rs` prüft das und dass jeder Code, den QML über `Texts` abfragt, existiert und jeder Eintrag in `ui_texts.rs` benutzt wird.
- Sprache: einfaches Englisch und einfaches Deutsch, Begriffe aus [glossary.md](glossary.md). Sätze haben höchstens 20 Wörter, Fachwörter (z. B. «daemon», «D-Bus», «Packs», «dry-run», «Klartext») kommen in Texten für Benutzer nicht vor; Ausnahmen sind Spec-Begriffe wie «getaktet» und «eingehängt» sowie Hinweise im Expertenmodus. Der Test `i18n/tests/simple_language.rs` prüft jeden Eintrag in `po/de/kestic.po`. Kein sichtbarer Text geht am Katalog vorbei: QML zeigt Texte nur über `i18n(…)`, `Texts.label(…)`/`Texts.labelArgs(…)` oder `appBackend.recoveryActionLabel(…)` (Beispielwerte in Platzhaltern wie Pfade ausgenommen), und Daemon und GUI geben keinen rohen Satz an Tray, Benachrichtigungen, Fenster oder System; das prüft `i18n/tests/no_raw_ui_texts.rs`. Der Smoke-Test `every_page_shows_simple_texts_in_the_gui_language` (`daemon/tests/m3_gui_smoke.rs`) öffnet jede Seite, jeden Editor, beide Assistenten, die Einstellungen und «Über Kestic» auf Englisch und Deutsch und prüft die sichtbaren Texte: kein englischer Text mit deutscher Übersetzung im deutschen Fenster, kurze Sätze, keine Fachwörter. Prüflisten für die menschliche Abnahme: `target/smoke-artifacts/texts-en-de.md` (alle Texte des Katalogs), `target/smoke-artifacts/m3-all-pages-texts-<Sprache>.tsv` (sichtbare Texte je Seite) und `m3-page-<Seite>-<Sprache>.png`.
